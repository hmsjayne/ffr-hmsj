# Final Fantasy Randomizer: HMS Jayne Prototype
Development guide

The directories/packages in the project are:

- asp: (Answer Set Programming) These are the files that support the solver used for key item placement.
    
- data: IPS patches, and source that could be used to rebuild them in many cases.

- doslib: Dawn of Souls library - Code to support reading and writing the ROM and associated data structures.

    Contained within "doslib" is a subpackage "gen". These files are autogenerated by `build_types.py` in
    "doslib".
    
- event: Code for assembling and disassembling event bytecode.

- labels: Text files that include NPC and location ID strings.

- randomizer: Final Fantasy Randomizer - Code to support randomizing the ROM.

- static: Static files used by the website.

- stream: library to support reading and writing of streams, used by `doslib`.

## Key Item Distribution

The Key items returned work like this. Suppose a Placement returned was:

```
[Placement(item='oxyale', location='king'),
Placement(item='canoe', location='sara')]
```

This means:

- Oxyale can be found at the location of the King of Cornelia.
- The Canoe can be found by Sara, the Princess of Cornelia.

This does not mean that the King will hand over Oxyale, or that the Princess will
give the canoe. Rather it means that the NPCs that usually provide those items,
in this case the Fairy and Sage (Lukahn in the randomizer, will be there and provide
those items.

This further means that going to the _Temple of Fiends_ will reveal that Garland has
kidnapped Lukahn, and freeing him will have him provide the canoe to the party.

At that point, the Fairy, in the King's spot, will provide Oxyale, now that their
beloved sage has been rescued(?).

enemy_stats_stream = rom.open_bytestream(0x1DE044, 194 * 32)

## Development setup

The reference implementation targets Python 3.12. Runtime dependencies are in
`requirements.txt`; test/lint tools are in `requirements-dev.txt`.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt
```

## Tests and the Python oracle

Run the fast test suite (no ROM required):

```bash
.venv/bin/ruff check .
.venv/bin/pytest -q
```

Run the ROM-backed golden tests by pointing at a clean Dawn of Souls ROM:

```bash
HMSJAYNE_ROM=/path/to/ff1-dos.gba .venv/bin/pytest tests/integration/test_golden.py
```

Run one deterministic case and emit a JSON manifest:

```bash
.venv/bin/python -m randomizer.oracle \
  --rom /path/to/ff1-dos.gba \
  --seed test \
  --trace /tmp/hmsj-trace.json
```

The oracle records hashes for the randomized ROM, the IPS patch, parsed stage
checkpoints, the patch manifest, and the input assets. `tests/golden/rom_hashes.json`
is the checked-in baseline used by the parity tests. Regenerate it only when a
behavior change is intentional:

```bash
.venv/bin/python tools/generate_goldens.py --rom /path/to/ff1-dos.gba
```

The base ROM is intentionally not stored in git. The golden tests verify its
SHA-256 before running cases.

## Core layout

The Phase 1 refactor separates loading, policy, and patching:

- `doslib/data_source.py` — filesystem/in-memory access to TSVs, scripts, and
  IPS files. The TypeScript port will implement the same interface.
- `randomizer/game_data.py` — loads ROM/TSV data once into a `GameData` model.
- `randomizer/placement.py` / `placement_application.py` — key-item placement
  data and applying placements to maps/vehicles.
- `randomizer/shops.py`, `spells.py`, `treasure.py`, `gear.py`,
  `map_updates.py` — individual randomization stages.
- `randomizer/events.py` — event script loading, preprocessing, compilation.
- `randomizer/patchset.py` — patch collection with duplicate-offset detection.
- `randomizer/progress.py` — progress reporting without printing from the core.
- `randomizer/api.py` — stable programmatic entry point used by the CLI and
  oracle.

The core no longer depends on the process working directory for data files;
relative asset paths resolve from the repository/bundle root.
